你是资深全栈工程师。在空目录中从零交付一个可运行的全栈项目「校园集」（campus-market）——校园二手交易与信用评价平台。这是课程实习交付物，要求功能复杂度明显高于电子阅读器、能现场演示、能讲清技术方案。

## 一、技术栈（固定）

- 后端 `api/`：Java 17 + Spring Boot 3.5.x + Maven Wrapper（本机无 mvn）+ Spring Data JPA + Flyway + MySQL 8 + Spring Security/JWT（access + refresh）+ Bean Validation + springdoc-openapi + JUnit 5 / MockMvc / H2
- 前端 `web/`：Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + Axios + ECharts
- 不使用 Redis / MQ / Docker / 真实支付，全部本地可跑
- 数据库连接信息由我提供，写入配置并支持环境变量覆盖；提供 `.env.example`，禁止提交密钥

## 二、文档先行（顺序不可颠倒）

1. `docs/PRD.md`：背景与目标、角色权限矩阵、功能清单（P0/P1）、核心业务流程、状态机（mermaid）、非功能需求、页面清单、验收标准
2. `docs/TECH_DESIGN.md`：架构图、目录结构、ER 图与完整表结构（含索引）、状态机落地实现、资金托管与信用分算法、JWT 鉴权链路、统一响应/异常/分页规范、API 一览、测试策略、运行手册
3. `AGENTS.md`（仓库根）：结构导航、编码规范、命令清单、迁移规则、里程碑进度表、禁止事项

三份文档写完后才允许写第一行业务代码，且实现必须与文档一致。

## 三、业务范围（P0 必须全部实现，不留 TODO 桩）

- 账号：注册 / 登录 / 刷新令牌 / 退出；校园认证（学号 + 校内邮箱验证码，验证码打日志）；未认证只能浏览
- 角色：STUDENT（买卖同体）、MODERATOR（审核员）、ADMIN
- 商品：多图上传、分类、成色、价格、标签；草稿 → 待审核 → 在售 → 交易中 → 已售 / 已下架；审核驳回必须填理由
- 检索：关键词 + 分类 + 价格区间 + 成色 + 排序 + 分页；收藏、浏览量、同类目推荐
- 交易：议价聊天（REST 轮询即可）→ 下单 → 钱包余额托管付款 → 面交 / 发货 → 买家确认收货 → 平台按 2% 收手续费后结算卖家；支持取消、退款、超时自动取消（定时任务）
- 评价与信用：订单完成后双向评价（评分 + 标签 + 文字）；信用分按成交率/好评率/纠纷率/举报次数加权计算并写入信用档案；低信用限制同时发布数量
- 风控：举报商品或用户 → 工单 → 审核员处理（下架 / 警告 / 封禁）；关键操作写审计日志
- 通知：站内通知 + 未读数
- 后台：审核队列、举报工单、用户管理、类目管理、数据看板（GMV / 订单量 / 新增用户 / 类目分布）

## 四、工程质量门槛

- 统一响应体 `{code, message, data, traceId}`；全局异常处理；DTO 校验；分页统一 `page` / `size`
- 资金变更全部在 `@Transactional` 内并用乐观锁 / 行锁，防重复扣款与超卖
- 前端 axios 拦截器（401 自动刷新、统一报错）、按角色的路由守卫
- 至少覆盖：托管下单、余额不足、重复确认收货、越权访问、信用分重算 的自动化测试
- 每个里程碑结束 `mvnw test` 与 `npm run build` 必须通过
